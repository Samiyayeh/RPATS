# Project Evaluation Rubric (Total: 25 pts)

| Criteria                                                                                                                              | Exemplary (5 pts)                                                                                                                                                                                                                                                                                                                                                                                                    | Proficient (3 pts)                                                                                                                                                                                                                                                                                                                                  | Developing (1–2 pts)                                                                                                                                                                                                                                                                        | Noncompliance (0 pts) |
| :------------------------------------------------------------------------------------------------------------------------------------ | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | :-------------------- |
| **Narrative & User Experience** (/5)<br>_How seamlessly does the student present the narrative and how fluid is the user experience?_ | **5 pts**<br>**User Journey Walkthrough:** The journey is effortless and logical; handles edge cases clearly.<br>**Interaction Flow:** The live demo shows zero lag or navigation errors; transitions are smooth and intuitive.                                                                                                                                                                                      | **3 pts**<br>**User Journey Walkthrough:** The user journey is clear but may miss minor edge cases.<br>**Interaction Flow:** The demo works well with only minor hiccups in navigation.                                                                                                                                                             | **2 pts**<br>**User Journey Walkthrough:** The journey is confusing or jumps around without context.<br>**Interaction Flow:** The demo has noticeable friction; the user gets "stuck" in the interface.<br>**Delivery:** The presenter struggles to explain how a user moves from A to B.   | **0 pts**<br>—        |
| **Standards, Accessibility & Technical Correctness** (/5)<br>_Alignment with ISO 9241-210, Accessibility, and Technical correctness._ | **5 pts**<br>**ISO 9241-210 Alignment:** Explicitly demonstrates how human-centered design principles drove the development.<br>**Accessibility:** The coded project passes major accessibility checks (color contrast, semantic HTML, keyboard navigability).<br>**Code Functionality:** The live/local demo is bug-free and renders accurately across intended viewports.                                          | **3 pts**<br>**ISO 9241-210 Alignment:** Mentions human-centered design but lacks deep evidence of the iterative cycle.<br>**Accessibility:** Good general accessibility, but misses minor details (e.g., missing alt tags or focus states).<br>**Code Functionality:** Project works, but minor visual bugs exist that do not break functionality. | **1 pt**<br>**ISO 9241-210 Alignment:** Fails to connect the design to user needs or standards.<br>**Accessibility:** Significant accessibility violations make the site difficult for impaired users.<br>**Code Functionality:** Critical bugs prevent the demo from functioning properly. | **0 pts**<br>—        |
| **AI Integration & Technical Complexity** (/5)<br>_Use of AI tools, coding difficulty, and technical defense._                        | **5 pts**<br>**AI Integration:** Showcases a sophisticated use of AI tools (for code generation, asset creation, or debugging) that significantly enhanced productivity or quality.<br>**Coding Difficulty:** Front-end implementation involves complex layouts, state management, or interactive logic beyond a static page.<br>**Defense:** Can answer tough technical questions regarding their coding decisions. | **3 pts**<br>**AI Integration:** Uses AI tools for basic tasks (e.g., generating text or simple code snippets) but with limited impact.<br>**Coding Difficulty:** Meets the requirements of a standard coded project; clean but standard implementation.                                                                                            | **1 pt**<br>**AI Integration:** Little to no mention of AI tools, or used them ineffectively.<br>**Coding Difficulty:** The project is overly simple (e.g., mostly boilerplate code) or relies too heavily on templates.                                                                    | **0 pts**<br>—        |
| **Submission Package Completeness** (/5)<br>_The completeness of the submission package._                                             | **5 pts**<br>**Handoff File:** The developer handoff (Figma/Zeplin/etc.) is perfectly organized with specs, assets, and redlines.<br>**Prototype vs. Code:** The coded result matches the high-fidelity prototype with pixel-perfect precision.                                                                                                                                                                      | **3 pts**<br>**Handoff File:** Handoff file is present but may lack some asset exports or specific measurements.<br>**Prototype vs. Code:** The code resembles the prototype, but there are noticeable spacing or font inconsistencies.                                                                                                             | **1 pt**<br>**Handoff File:** Missing or disorganized files.<br>**Prototype vs. Code:** The coded project looks significantly different from the design prototype.                                                                                                                          | **0 pts**<br>—        |
| **Visual Appeal & UX Quality** (/5)<br>_The visual appeal and the overall "feel" of the product._                                     | **5 pts**<br>**UX Quality:** The interface is delightful, modern, and aesthetically pleasing. Visual hierarchy guides the user's eye naturally.<br>**Consistency:** Typography, color palette, and spacing are consistent throughout the live demo.                                                                                                                                                                  | **3 pts**<br>**UX Quality:** The design is functional and clean, but lacks "polish" or emotional appeal.<br>**Consistency:** Mostly consistent, with a few rogue fonts or clashing colors.                                                                                                                                                          | **1 pt**<br>**UX Quality:** The design feels outdated, cluttered, or visually confusing.<br>**Consistency:** Inconsistent UI elements (e.g., different button styles for the same action).                                                                                                  | **0 pts**<br>—        |
